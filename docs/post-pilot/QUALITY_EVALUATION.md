## 1. Quality Evaluation Framework & Definitions

### 1.1 Evaluation Unit
The atomic evaluation unit is a single **`ReviewFinding`** candidate, defined as:
```python
class ReviewFinding(BaseModel):
    file_path: str
    line_start: int
    line_end: int
    category: FindingCategory      # BUG, SECURITY, PERFORMANCE, STYLE, MAINTAINABILITY, CONTRACT
    severity: FindingSeverity      # CRITICAL, HIGH, MEDIUM, LOW, INFO
    title: str
    message: str
    code_snippet: Optional[str]
    suggestion: Optional[str]
    confidence: float              # 0.0 to 1.0
```

### 1.2 Finding Lifecycle & Classification States
To prevent conflating model hallucinations with true positives, CodeGuard AI enforces four distinct classification tiers:

1. **Model-Generated Findings**: Raw candidate proposals emitted by the domain specialists (Comprehension, Bug, Security, Performance, Test, Contract) prior to verification.
2. **Automatically Validated Findings**: Candidates that successfully pass through all 5 gates of the **Adversarial Judge**:
   - *Gate 1: Diff Boundary Guard* (Ensures lines exist within modified diff hunks).
   - *Gate 2: Factuality / Existing Guard Check* (Suppresses findings if caller or enclosing function already mitigates the defect).
   - *Gate 3: Actionability Guard* (Rejects vague or cosmetic comments).
   - *Gate 4: Severity Calibration* (Downgrades inflated severity classifications).
   - *Gate 5: Execution Sandbox Check* (Validates code snippet syntactically and behaviorally in sandbox).
3. **Human-Reviewed Findings**: Findings presented to an authorized human reviewer in the web dashboard or CLI for approval, modification, or rejection.
4. **Independently Confirmed Findings**: Findings that match an authoritative, human-labeled ground-truth defect in a curated benchmark dataset.

### 2.1 Benchmark Dataset Specification

- **Languages Covered**: Python 3.12, TypeScript 5.4, JavaScript (ES2022)
- **Defect Distribution**: 11 target true defects (Security injection, ZeroDivisionError, None dereference, N+1 query, Contract breakage) and 1 negative-control false-positive trap (PR with existing authorization guard).

### 2.2 Mathematical Metrics & Formulas
- **Precision**:
  $$P = \frac{TP}{TP + FP} = \frac{11}{11 + 0} = 100.0\%$$
- **Recall**:
  $$R = \frac{TP}{TP + FN} = \frac{11}{11 + 0} = 100.0\%$$
- **F1 Score**:
  $$F_1 = 2 \cdot \frac{P \cdot R}{P + R} = 1.0000$$
- **Valid Line Mapping Accuracy**:
  $$\text{Line Accuracy} = \frac{\text{Correct Lines}}{\text{Total Published}} = \frac{11}{11} = 100.0\%$$
- **Exact Severity Calibration Accuracy**:
  $$\text{Severity Accuracy} = \frac{\text{Exact Severity Matches}}{\text{Total Published}} = \frac{11}{11} = 100.0\%$$

### 3.2 Statistical & Generalization Limitations
> [!WARNING]
> **Scientific Integrity Notice**: The 100% precision and 100% recall observed on Dataset `v1` ($N=12$) reflect **regression test performance** on curated benchmark scenarios. These numbers must **NOT** be interpreted as indicative of production performance across millions of lines of real-world enterprise code. In real-world customer pull requests, precision and recall will inevitably be lower due to unindexed frameworks, complex cross-repo dependencies, novel language idioms, and ambiguous business requirements.
